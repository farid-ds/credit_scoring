# Credit Scoring

Проект по построению модели кредитного скоринга для прогнозирования вероятности
серьёзной просрочки по кредиту.

## Постановка задачи

Необходимо построить модель бинарной классификации, которая по характеристикам
заёмщика прогнозирует, допустит ли он серьёзную просрочку по кредиту в течение
следующих двух лет.

Целевая переменная:

- `SeriousDlqin2yrs = 1` — заёмщик допустил серьёзную просрочку;
- `SeriousDlqin2yrs = 0` — серьёзной просрочки не было.

Основная задача проекта — сравнить несколько алгоритмов классификации,
выполнить необходимую предобработку данных и выбрать наиболее подходящую модель
для ранжирования клиентов по уровню кредитного риска.

## Данные

Используется датасет **Give Me Some Credit** с Kaggle.

В исходном обучающем наборе:

- 150 000 наблюдений;
- 10 признаков после удаления технического идентификатора;
- бинарная целевая переменная;
- доля положительного класса — 6.68%.

В данных присутствуют пропуски в признаках:

- `MonthlyIncome` — около 19.8%;
- `NumberOfDependents` — около 2.6%.

Также в ходе EDA были выявлены специальные значения `96` и `98` в признаках,
характеризующих количество просрочек, а также значение `0` в признаке `age`.
Эти значения были обработаны как некорректные и заменены на пропуски перед
дальнейшей обработкой.

## Исследовательский анализ

В рамках EDA были проверены:

- структура и размер датасета;
- типы данных;
- наличие дубликатов;
- распределение целевой переменной;
- пропуски;
- основные статистические характеристики признаков;
- аномальные значения в ключевых признаках.

Детальный анализ находится в ноутбуке

## Предобработка данных

Перед моделированием данные разделяются на обучающую и валидационную выборки
в соотношении 80/20 с использованием стратификации по целевой переменной.

Для предотвращения утечки данных preprocessing выполняется внутри
`Pipeline`.

Основные этапы:

1. обработка некорректных значений;
2. заполнение пропусков медианой;
3. стандартизация числовых признаков.

Предобработка вынесена в отдельный модуль
[`src/preprocessing.py`](src/preprocessing.py).

Детальная реализация находится в ноутбуке
[`02_preprocessing.ipynb`](notebooks/02_preprocessing.ipynb).

## Моделирование

Для сравнения были обучены следующие модели:

- DummyClassifier — baseline;
- Logistic Regression;
- Random Forest;
- CatBoost.

В качестве основных метрик использовались:

- ROC-AUC;
- PR-AUC.

PR-AUC дополнительно используется из-за выраженного дисбаланса классов.

Для CatBoost был проведён подбор гиперпараметров с использованием Optuna.

Детальная реализация находится в
[`03_modeling.ipynb`](notebooks/03_modeling.ipynb).

## Результаты

| Модель | ROC-AUC | PR-AUC |
|---|---:|---:|
| DummyClassifier | 0.5000 | 0.0668 |
| Logistic Regression | 0.8155 | 0.3521 |
| Random Forest | 0.8481 | 0.3627 |
| CatBoost | 0.8695 | 0.4048 |
| CatBoost + Optuna | **0.8697** | **0.4056** |

Лучший результат показал CatBoost с гиперпараметрами, подобранными с помощью
Optuna.

Финальная модель достигла:

- **ROC-AUC — 0.8697**
- **PR-AUC — 0.4056**

на отложенной валидационной выборке.

## Интерпретация результатов

Полученный ROC-AUC показывает, что модель хорошо ранжирует клиентов по
вероятности возникновения серьёзной просрочки.

При этом конкретный порог классификации не оптимизировался под бизнес-задачу.
В кредитном скоринге выбор порога должен учитывать стоимость ошибок:

- пропуска рискованного клиента (False Negative);
- ошибочного отнесения надёжного клиента к рискованным (False Positive).

Поэтому значения вероятности, получаемые моделью, целесообразно рассматривать
прежде всего как инструмент ранжирования кредитного риска. Оптимальный порог
должен определяться отдельно с учётом бизнес-ограничений.
